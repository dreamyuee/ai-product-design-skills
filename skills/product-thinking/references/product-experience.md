# 产品体验观察

## 渐进式引导与行为触发

Onboarding 未完成的连接和配置，可在后续相关任务中补引导。解释连接带来的具体结果，复用已有上下文，只补缺失条件；支持忽略、跳过、关闭和频控。等待 AI 回答时可提供探索入口，需支持回到当前任务，避免遮挡回答或造成打扰。

比较内容启发（相关教程、模板、案例）和工作现场触发（已授权任务中的明确重复需求）。说明识别依据，不把一次性任务直接判为周期任务，不为识别扩大数据访问。承接触发、试运行、检查修正、保存及按需启用重复执行；分清建议、创建、运行、定时和对外发送的授权。验证相关性、误判、试运行成功、复用、工作量节省、忽略与成本。

## 入口与导航

分析入口分别承担产出类型、任务、专项工具/Agent、工作流、学习发现、开发者接入、商业化或账户功能中的什么角色。混合分类可能服务不同用户，也可能增加理解负担；结合任务判断，不预设好坏。

检查新用户理解、熟练用户回访、高频任务与商业入口优先级、New/折扣/高亮的注意力竞争，以及命名和扩展性。没有证据时将设计意图和效果标为推断。

## Agent 管理与多 Agent

专项 Agent 适合任务明确且能识别所需能力；总管理 Agent 适合目标明确但路径不清的任务。入口需解释当前执行者、能力、状态，切换时明确历史、任务、权限与上下文如何处理，不假设竞品支持切换。

只有可独立并行子任务、不同专业能力/权限/工具、独立审查或阶段交接带来的收益值得协调成本时才推荐多个 Agent。比较单 Agent，不把数量当价值。

明确谁拆任务、选执行者和汇总；输入输出及完成标准；并行与依赖；失败、超时、取消、部分成功；递归、循环、重复执行和累计预算；用户查看、修正与接管方式。竞品是否支持 Agent 调用 Agent 需官方或操作证据。

## 共享上下文

分别分析用户偏好、公司资料、任务要求、对话、文件与外部数据、中间结果、已确认决策、工具授权和凭据。不要用共享记忆概括全部。

对每类信息定义任务/Agent/项目/工作区/用户作用范围、读写权限、来源时间与可信度、更新冲突过期撤销规则、用户查看修改删除方式，以及交接时传原文、摘要、结构化状态还是引用。凭据不应作为普通对话上下文共享，授权通过适当的权限机制使用。

不默认所有 Agent 共享全部历史。传递相关的必要信息，检查遗漏、错误传播、隐私和上下文成本。分清用户纠正、系统推断和已确认规则，不因一次拒绝静默修改全局规则。

## 按需授权（Just-in-time permission）

任务真正需要访问某项数据或执行某个动作时，再申请对应权限。把它作为设计原则，结合任务依赖、平台授权粒度和组织要求判断，不把效果当成已验证结论。

- 未确定任务时可介绍或推荐 Connector，说明具体收益并允许稍后连接；不要把业务想提升连接率直接当成用户必须授权的理由。
- 已确定任务且缺少必要权限时，在依赖步骤前解释为何需要、访问哪个账号和哪些数据、能做什么、是否持续使用，再请求可实现的最小权限。公开数据任务不默认要求私人账号连接。
- 外部发送、修改或删除前，检查写入权限、用户意图和已有动作授权；按影响、可逆性与既有授权设置预览或确认，不将连接账号视为批准所有动作，也不要求每次低风险操作重复确认。
- 分清账号连接、权限授予和具体动作批准。已有有效且范围足够的授权直接复用；新增范围时再申请。技术只能一次申请宽范围权限时，明确说明限制，并比较替代路径与接入时机，不能承诺做不到的细粒度授权。
- 拒绝、取消或连接失败时保留任务输入与执行进度，说明受阻步骤；可行时提供公开数据、手动上传或缩小任务等替代方案。授权成功后从安全检查点恢复，防止重复执行和重复扣费。
- 权限过期或撤销时暂停依赖步骤及相关后台任务，告知恢复方法，不静默扩权。设置中提供授权范围查看与断开入口；记录授权和执行状态，凭据不进入普通共享上下文。
- 授权入口随任务依赖安排，可以在任务配置页、执行前面板或会话中，不固定只能放 Chat 开始、等待或结束阶段。

例如分析 Gmail 未回复客户邮件时请求必要读取权限；公开竞品研究通常不需要 Gmail。后续发送邮件需单独检查写入与动作授权。例子用于解释原则，具体 scope 和能力需核实。

验证授权环节流失、授权后任务成功率、首次成功耗时、取消后恢复率和非必要提示频次，并观察权限范围与运行成本；不只优化连接率。

## 信任与渐进披露

先判断哪些角色在哪个决策点需要控制、价格、透明度、隐私、权限和安全信息。普通用户可能关注结果、费用与自动执行；重度用户/开发者可能关注工具、额度和日志；管理者/采购可能关注团队成本、权限与审计。具体需求待验证，不把分群假设当普遍事实。

关键决策信息直接可见，技术细节按需展开。授权、付费、发送与持续执行前说明后果；折叠不能隐藏足以改变决定的费用、权限和数据用途。

Pricing 评价可能缓解付费疑虑：检查目标用户相关性、具体场景与结果、可信度、来源及选择性展示。评价不能单独证明普遍效果。
